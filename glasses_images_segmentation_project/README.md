# Ретроспективний Аналіз: Проєкт Сегментації Окулярів з U-Net

---

## Контекст проєкту

Цей документ є технічною ретроспективою проєкту з бінарної семантичної сегментації окулярів. Мета — не просто задокументувати початкові результати, а проаналізувати прийняті тоді рішення крізь призму набутого досвіду та сучасних інженерних практик.

## Ключові показники оригінального проєкту

- Задача — бінарна сегментація окулярів;
- Результат (тестова вибірка) — Dice 0.8276, IoU 0.7075;
- Складність моделі — ~31M параметрів;
- Швидкодія (CPU, TFLite FP32) — ~14.2 с/зображення.

---

## 1. Архітектура моделі

**Підхід тоді.** Реалізована «чиста» архітектура U-Net з нуля в TensorFlow/Keras. Модель складалася з симетричних блоків кодера (`encoder_block`) з `Conv2D`, `BatchNormalization` та `MaxPool2D`, і блоків декодера (`decoder_block`) з `Conv2DTranspose` для підвищення роздільної здатності. Skip-зв'язки реалізовані через `Concatenate` для поєднання ознак.

**Примітки (напрями покращень).**
- Використання lightweight-бекбонів, зокрема **MobileNetV3**, у парі з U-Net-декодером;
- Розгляд **SegFormer** для сцен із потребою в глобальному контексті;
- Інтеграція **attention-gates** у skip-зв’язки для покращення U-Net.

---

## 2. Дані та конвеєр (Data Pipeline)

**Підхід тоді.** Конвеєр побудований на `tf.data`. Шляхи до файлів збиралися за допомогою `glob`. Для читання зображень використовувалася бібліотека OpenCV (`cv2.imread`), а інтеграція в граф TensorFlow виконувалась через обгортку `tf.numpy_function`. Дані нормалізувалися діленням на `255.0` та подавалися в модель батчами з використанням `.prefetch()` для оптимізації.

**Примітки (напрями покращень).**
- Використання нативного TensorFlow I/O (`tf.io.read_file → tf.image.decode_*`);
- Інтеграція аугментацій безпосередньо в граф (`tf.image`, `tfa.image`, RandAugment);
- Застосування формату **TFRecord** з кешуванням для великих датасетів.

---

## 3. Процес навчання: функції втрат та планування LR

**Підхід тоді.** Оптимізатор **Adam** з фіксованою початковою швидкістю навчання `1e-4`. Функція втрат — **Binary Cross-Entropy (BCE)**. Контроль процесу — через набір Keras Callbacks: `ModelCheckpoint` для збереження найкращої моделі, `ReduceLROnPlateau` для адаптивного зниження LR та `EarlyStopping` для запобігання перенавчанню.

**Примітки (напрями покращень).**
- Застосування комбінованої функції втрат **Focal Loss + Dice Loss**;
- Використання планувальника **CosineDecay** з прогрівом (warmup);
- Інтеграція інструментів трекінгу експериментів **Weights & Biases** або **MLflow**.

---

## 4. Оцінка та готовність до розгортання

**Підхід тоді.** Оцінка проводилася на тестовій вибірці з використанням метрик **Dice** та **IoU** (`sklearn.metrics`). Модель була конвертована у формат **TFLite FP32** за допомогою `tf.lite.TFLiteConverter` для вимірювання швидкодії на CPU, яка виявилася неприйнятною (~14.2 с/зображення).

**Примітки (напрями покращень).**
- Проведення **Post-Training Quantization (PTQ)** до **INT8** з калібрацією репрезентативним датасетом;
- Використання **дистиляції знань** для побудови компактної моделі-студента;
- Профілювання на цільовому пристрої з використанням делегатів (**NNAPI**, **GPU Delegate**).

---

## 5. Інженерні практики та відтворюваність

**Підхід тоді.** Проєкт реалізовувався у **Jupyter Notebook**. Логування результатів тренування велося у CSV-файл за допомогою `CSVLogger`, а найкраща модель зберігалася через `ModelCheckpoint`, що забезпечувало базовий рівень відтворюваності експерименту.

**Примітки (напрями покращень).**
- Структурування коду за директоріями `src/`, `configs/`, `notebooks/`, `scripts/`, `data/`, `models/`, `reports/`;
- Використання **YAML-конфігів** і сидування (random seeds) для відтворюваності;
- Впровадження **юніт-тестів** для пре- та постпроцесингу (pytest);
- Налаштування базового **CI** для smoke-тестів на малому датасеті (GitHub Actions).
